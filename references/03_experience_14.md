# 경험 개요 14항목 템플릿 (3단계)

각 경험을 아래 14항목으로 작성한다.

```markdown
## [경험 번호·명칭]
1. 경험 명칭
2. 기간
3. 설명
4. 목적
5. 역할 (본인 담당 범위 — 단독/공동 명시)
6. 목표(성과지표)                     ← ⚠️ 지원자만 아는 값
7. 가장 어려웠던 문제(핵심 1가지) / 향후 직무에서 발생할 법한 문제  ← ⚠️
8. 원인                                ← ⚠️
9. 해결과정 (전문성이 드러나도록) — 가 / 나 / 다   ← ⚠️
10. 문제해결결과                        ← ⚠️
11. 전체 경험(프로젝트) 결과 및 성과     ← ⚠️
12. 배운점, 느낀점
13. 직무와의 연관성
14. 핵심키워드
```

## 규칙
- **9번 해결과정은 반드시 3단계(가·나·다)**로, 해당 프로젝트의 실제 스택에 맞는 전문성이
  드러나게 쓴다. (예: GraphQL N+1 → DataLoader 도입 / 커넥션풀 튜닝 / RAG 청킹·그라운딩 등)
- **6·7·8·9·10·11번은 지원자만 아는 사실**이다. 모르면 기술적으로 타당한 시나리오로 채우되
  반드시 `⚠️(예시 — 실제 경험으로 교체)`로 표시한다. 이 부분이 자소서 신뢰성의 핵심이다.
- 7번은 과거 문제를 **향후 직무에서 생길 문제**와 연결해, 문제의식이 직무로 이어지게 한다.

## 직무 방향 재구성 옵션
사용자가 특정 직무(예: AI·클라우드·백엔드)를 겨냥하면, 같은 경험이라도:
- 순서를 그 직무 적합도 순으로 재배치하고,
- 7~13번의 문제·해결·연관성을 그 직무 언어로 다시 쓴다.
  (예: AI 직무면 RAG·에이전트·모델 파이프라인·평가/관측 관점으로)

## 작성 후
하단에 체크리스트: ⚠️ 정량 성과·핵심문제·해결과정 교체, 기간 확정, 수상·평가 결과 반영,
본인 담당 범위 명시.
